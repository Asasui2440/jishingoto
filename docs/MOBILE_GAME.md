# フェーズ2のコンパクトUI

## 表示の方針

- 準備・体験・ふりかえりの3画面。出発地点・避難先選択とルート比較は同じ地図で切り替える。
- 地図と今必要な操作を常時表示。詳細説明・設定・全避難先・判断の根拠はネイティブdialogのボトムシートへ移す。
- 色に加え、A/B・番号・チェック・アイコンで状態を伝える。地形評価を安全ランキングとして表示しない。
- 主要操作は画面下部へ。短い画面や拡大文字では内容部分だけスクロールでき、開始ボタンは残す。
- 現在地取得や次の行動の保存は短いトーストで通知。失敗は消える通知だけで済ませず、操作付近に表示する。

## 維持した体験

Google Mapsの住所検索・現在地取得・地図タップ、避難先検索、徒歩経路比較、地形評価バックエンドは継続して使用する。APIの失敗をサンプル結果で自動置換しない。

歩行中のコマ移動・判断地点・選択肢・迂回と残りの出題・制限時間・早送り・経路履歴を維持する。Street Viewは「周りを見る」で開く。説明・設定・周辺確認中は移動と判断タイマーを一時停止し、時間切れでも自動回答しない。

ふりかえりでは選んだ行動の利点・注意点・判断のヒント・出典をシートで確認できる。「次に確かめること」の保存、別ルートへの再挑戦、部屋の体験との連携も維持する。

ふりがな・文字サイズ・モード・地形解析の設定は準備画面右上の「遊び方・設定」に集約する。練習であり実災害時の安全を保証しない旨はフッターに残す。

## 検証と限界

`npm run test:e2e` は実際のページを操作する。サンプルモードで比較、3地点の判断、迂回、時間停止・無制限化、ふりかえりの出典・履歴、保存・再読込・再挑戦を検証する。320×568、360×640、390×844で主要操作の可視範囲とページ全体の横・縦スクロールを確認する。詳細シート内のスクロールは許容する。

APIモードではGoogle通信を遮断した320×568・特大文字のケースも検証し、失敗時にも検索・現在地・設定と主要操作へアクセスできることを確認する。これはGoogleの結果を偽装するテストではなく、失敗時のUIの検証。

サンプルE2Eの成功はGoogle APIの利用可否を保証しない。実APIのブラウザ診断は開発サーバー起動中に `npm run check:maps`。Mapsの初期化状態とキーを伏せたエラーを出力し、`artifacts/maps-api-preview.png`へ画面を保存する。現在地そのものは取得しない。

Google Cloudのブラウザキーには、実際に開くドメイン・ポートに合ったHTTPリファラー制限が必要。3010番で開発するなら、そのローカルURLも許可対象に追加する。公開版の設定は [MAPS_SETUP.md](MAPS_SETUP.md) を参照。キー値・ローカル環境変数・テスト成果物はGitへ登録しない。
