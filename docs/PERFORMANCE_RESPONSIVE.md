## 画像生成

- モデルと1536×1024の解像度を維持し、既定画質をhighからmediumへ。明示的な `OPENAI_IMAGE_QUALITY=high` は有効です。
- PNGからJPEG（output_compression=85）へ変更して転送量を削減。
- 元写真との比較には対象ごとの変更点だけを渡し、生成用プロンプト全文の重複送信を削減。構造・物の追加・マスクの確認は維持。
- 110秒での打ち切りを、再試行も含め175秒に変更。比較25秒、Route Handler 240秒、クライアント225秒。
- 429・503の一時拒否だけ最大1回再試行。Retry-Afterが5秒超なら再送せず、利用上限・タイムアウト・画像不一致・通信結果が不明な場合も自動再生成しない。
- 入出力のbase64文字列を4,000,000文字以下に制限。画像・個人情報・APIキーをログへ出さず、工程の所要時間とエラー分類だけを記録。
- 結果画面で生成開始からの経過時間を表示。画面を切り替えても同じ生成処理を再利用。

公式資料：[OpenAI画像生成](https://developers.openai.com/api/docs/guides/image-generation)、[Vercel Functionsの上限](https://vercel.com/docs/functions/limitations)。

## 画面幅

スマホ固定の最大幅402px／480pxを解消。本文幅に応じたCSSコンテナクエリでクイズ・振り返りを2列にします。jishingoto3の目次は画面幅1280px以上のみ表示し、タブレットでは本文に幅を使います。詳細・設定パネルは最大720〜760pxです。

対象のブラウザテストは `tests/responsive.spec.ts`。320、600、768、1024、1366pxで、ホーム、設定、振り返り、詳細、まとめ、チェックリスト、クイズを確認します。API処理は固定データを使い、実測とは別に検証します。
