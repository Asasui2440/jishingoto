# フェーズ2：ひなん経路シミュレーション

自宅付近から避難場所までの**実在する経路**を題材に、地震後の街中で起こり得る危険に対して
判断し、経路を選び直す体験。フェーズ1（部屋の中）の続きにあたる。

## 画面の流れ

| ルート | 内容 | 仕様の対応 |
|---|---|---|
| `/evac` | 自宅付近の指定（住所検索・現在地・地図タップ）と、近くの避難場所の確認 | 3-①② |
| `/evac/routes` | 徒歩の候補経路2本の比較・制限時間の設定 | 3-③④、5 |
| `/evac/walk` | ストリートビューで経路を歩き、途中で判断（2〜3件） | 3-⑤⑥⑦、6、7 |
| `/evac/report` | 結果レポート | 3-⑨、8 |

入口はトップ（`/`）の「ひなん経路をためす（フェーズ2）」。

## Google Maps Platform

`.env.local` に置く：

```
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=...
```

有効にする API：**Maps JavaScript API**、**Routes API**、**Geocoding API**、
**Places API (New)**。キーには HTTP リファラ制限をかけること。

キーがない場合は「遊び方・設定」でモック版を選ぶ。簡易マップ、合成した経路、
自作イラストを使い、同じ画面の流れを最後まで確認できる。

### 使っている API

| 用途 | いま | 備考 |
|---|---|---|
| 地図・現在地 | Maps JavaScript API＋`navigator.geolocation` | |
| 住所から地点を出す | `Geocoder`（Geocoding） | 「住所・駅名でさがす」欄 |
| パノラマ探索 | `StreetViewService.getPanorama()`（緯度経度＋半径120m、屋外のみ） | パノラマ ID は保存しない |
| 徒歩経路・代替経路 | Maps JavaScript APIのRoutes Library | 地図と同じブラウザキーを使用 |
| 近くの避難場所 | ①国土地理院「指定緊急避難場所データ」→②Places `Place.searchNearby()` | API失敗時に固定候補へ自動変換しない |

必要な API：**Maps JavaScript API**、**Routes API**、**Geocoding API**、
**Places API (New)**。

### 避難場所をどこから取っているか

1. **国土地理院「指定緊急避難場所データ」**（`skhb04` = 地震）のタイル GeoJSON を、
   指定地点の周辺から読む。公的データなので、これが取れたときは
   `指定緊急避難場所` としてそのまま出す。
2. 取れなければ **Google Places** で公園・小学校・公民館などを近い順に。
   これは自治体の指定ではないので、カードに
   「Google マップの施設情報（避難場所の候補）」と出どころを書き、
   自治体の一覧で確認するよう促す。
3. API版でどちらも取得できなければエラーを表示する。モック版だけが固定候補を使う。

出どころは `Shelter.source` に入っていて、画面ではカードごとにそのまま表示している。

### ストリートビューを歩く

判断欄はStreet Viewの上に重ねる。出題・1秒の案内・回答でパノラマのサイズを変えず、
その地点のライブ表示を背景に維持する。地図は地図アイコン、案内は「使い方」で示し、
準備画面にはAPI版／サンプル版の切り替えを直接表示する。状態表示は青、主要操作は黄色。
目的地の方角は視点に応じて回る矢印で示す。

移動は曲がり角で区切り、隣接リンクの更新完了を待ってから次へ進む。
辿れない区間への座標ジャンプは行わず、想定図へ切り替える。

経路の全頂点を記録しつつ、操作上は約65mを一歩として進む。「進む」または
「自動で歩く」でStreet Viewの隣接パノラマを道沿いにたどり、判断地点で必ず止まる。
迂回を選ぶと現在地点から経路を引き直し、通った道と未体験の判断地点を維持する。

最初だけ緯度経度からパノラマを探し、以後は隣接パノラマのリンクをたどる。
読み込み完了前は次の操作を無効にし、18秒で取得できなければ想定図へ切り替える。
地図・説明・設定を開いている間は、歩行と判断タイマーを停止する。

## 守っているルール

### 安全表現（仕様 11）
- 実在の建物・塀・道路が壊れると**断定しない**。危険はすべて「〜した想定」と書く。
- 画面上部に「想定シナリオ」の帯を**常時**出す（`/evac/walk`）。
- ストリートビューの上に重ねるのは、半透明の想定範囲と番号だけ。
  実在の建物が損壊して見える加工はしない。
- 「現在のストリートビュー画像だけでは安全性を判定できません」を下部シートに常時出す。
- 経路の説明に「安全です」と書かない。距離・時間・イベント数・曲がる回数など、
  **経路データから言えることだけ**を並べる（`routeNotes()`）。

### データの扱い（仕様 9）
- ストリートビューの画像はアプリ側で保存・キャッシュしない。
- パノラマ ID に依存せず、毎回 緯度経度から `getPanorama()` で取り直す。
- 保存するのは、指定した地点・選んだ避難場所・経路の座標・イベント ID・回答だけ
  （`jishingoto.evac.v2` / `sessionStorage`）。
- 位置情報の使いみちを `/evac` で先に説明する。

### 帰属表示（仕様 7・14）
- Street View の標準コントロールは減らしているが、Google のロゴと帰属表示は消さない。
- 下部シートはパノラマの**外**に置き、パノラマの下端に何も重ねない。

### AI とルールエンジンの分担（仕様 10）
- 判断イベントの中身・選択肢の優先順位は `evac-content.ts` の**ルールデータ**。
  ストリートビューの画像を見て判定してはいない。
- ストリートビュー画像を AI に送る解析は、利用条件と権利処理を確認したあとの将来機能。

### 判断と結果（仕様 6・8）
- 選択は3択（そのまま進む／距離を取る・待つ／迂回する）。正解を当てるクイズにしない。
- 選択直後は短いフィードバックだけ。利点と注意点は結果レポートでまとめて出す。
- 迂回を選ぶと、この先の判断地点が別ルートのものに差し替わる。
- 結果は点数を主役にせず、「避けられた危険」と「次回の判断基準」、
  そして**平常時に確認すること**をひとつ選んでもらう形にしている。
- 制限時間は既定10秒。時間設定から「10秒ふやす」「制限なし」を選べる。
  時間が0秒になっても自動回答せず、本人が行動を選ぶ。

## ハッカソン版の範囲（仕様 13）

- 対象地域：どこでも可（住所・現在地・地図タップで指定）。デモ地点は文京区大塚 付近
- 避難場所：公的データ／Places から近い順に最大5件（取れないときはデモ2件）
- 候補経路：2本
- 判断地点：最短ルート3地点／もう一方2地点
- イベント：ブロック塀・落下物・通行止め（各3択）
- 結果レポート：1画面

## まだ入っていないもの

- ハザードマップ（対象災害に応じた補助情報）の重ね合わせ
- 避難場所が利用できない想定への分岐
- 夜間・雨天の想定
- 成功指標の計測（イベント送信）
