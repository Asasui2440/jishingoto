# フェーズ2：ひなん経路シミュレーション

自宅付近から避難場所までの**実在する経路**を題材に、地震後の街中で起こり得る危険に対して
判断し、経路を選び直す体験。フェーズ1（部屋の中）の続きにあたる。

## 画面の流れ

| ルート | 内容 | 仕様の対応 |
|---|---|---|
| `/evac` | 自宅付近の指定（住所検索・現在地・地図タップ）と、近くの避難場所の確認 | 3-①② |
| `/evac/routes` | 徒歩の候補経路2本の比較・制限時間の設定 | 3-③④、5 |
| `/evac/walk` | ストリートビューで経路を歩き、途中で判断（2〜3件） | 3-⑤⑥⑦、6、7 |
| `/evac/report` | 結果レポート | 3-⑨、8 |

入口はトップ（`/`）の「ひなん経路をためす（フェーズ2）」。

## Google Maps Platform

`.env.local` に置く：

```
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=...
```

有効にする API：**Maps JavaScript API**、**Routes API**、**Geocoding API**。キーには HTTP リファラ制限をかけること。

キーがない場合は「遊び方・設定」でモック版を選ぶ。簡易マップ、合成した経路、
自作イラストを使い、同じ画面の流れを最後まで確認できる。

### 使っている API

| 用途 | いま | 備考 |
|---|---|---|
| 地図・現在地 | Maps JavaScript API＋`navigator.geolocation` | |
| 住所から地点を出す | `Geocoder`（Geocoding） | 「住所・駅名でさがす」欄 |
| パノラマ探索 | `StreetViewService.getPanorama()`（開始時のみ緯度経度＋半径40m、屋外の最近傍） | パノラマ ID は保存しない |
| 徒歩経路・代替経路 | Maps JavaScript APIのRoutes Library | 地図と同じブラウザキーを使用 |
| 近くの避難場所 | 国土地理院「指定緊急避難場所データ」を災害種別で絞り込み | API失敗時に固定候補へ自動変換しない |

必要な API：**Maps JavaScript API**、**Routes API**、**Geocoding API**。

### 避難場所をどこから取っているか

1. **国土地理院「指定緊急避難場所データ」**（地震 `skhb04`／洪水 `skhb01`）のタイル GeoJSON を指定地点の周辺から読む。
2. 対応フラグ（地震 `disaster4`／洪水 `disaster1`）が1の場所だけを表示する。名称だけで災害への対応を推測しない。詳細には公開データ内の全災害種別フラグを表示する。
3. 取得失敗は再試行を案内する。Placesの施設候補には置き換えない。モック版だけが固定の練習用候補を使う。

出どころは `Shelter.source` に入っていて、画面ではカードごとにそのまま表示している。

### ストリートビューを歩く

判断欄はStreet Viewの上に重ねる。出題・1秒の案内・回答でパノラマのサイズを変えず、
その地点のライブ表示を背景に維持する。地図は地図アイコン、案内は「使い方」で示し、
準備画面にはAPI版／サンプル版の切り替えを直接表示する。状態表示は青、主要操作は黄色。
目的地の方角は視点に応じて回る矢印で示す。

API版の移動命令は、現在のパノラマの `links` にあるIDだけを受け取る。
任意座標への移動・経路上の予定地点への追従・複数地点の早送りは行わない。
開始時だけ近くの屋外パノラマを検索し、以後は選んだ隣接地点へ一歩ずつ移動する。
移動の前後には選んだ隣接リンクの方向へ視点を向ける。停止中はドラッグで自由に見回せる。
地図を操作しても現在地は変更しない。
ルートから外れたときは体験中のノード履歴をたどる隣接リンクを青い「ルートに戻る」で示す。
履歴は戻った地点まで短縮し、戻る操作で行き来を繰り返さない。再読込後など履歴がない場合は推測で戻る道を表示しない。

地図の現在地・通った道はStreet Viewから得た実座標を使う。移動完了を確認してから
経路上の進捗・残り距離と時間の目安・判断地点を更新する。判断は実際に近づいた地点だけで提示する。
未体験の判断を回答済みにはせず、予定経路から外れても撮影地点を別の座標へ補正しない。
迂回経路は実際の撮影地点から取得し、すでに通った道を維持する。

歩行開始前に、Routes APIの経路に沿ってStreet Viewの隣接リンクを探索する。
開始ノードから到着ノードまで接続済みのノード列を構成できた場合だけ歩行を開始できる。
探索は経路付近に限定し、上限400地点・45秒で打ち切る。途中の座標をつないで接続を捏造しない。
未接続・取得失敗の場合は再確認または別ルートの選択を案内する。
準備したノード列は体験中のメモリに保持し、歩行中に方角から進路を推測し直さない。
接続が変わっていた場合も経路を消さず、その場で待機して再確認を案内する。
「自動で歩く」は判断・地図・説明の表示中もONを保持する。回答後の案内が終わるか、
地図を閉じると再開する。迂回の場合は新しいノード列の準備完了後に再開する。
明示的な一時停止、到着、歩行画面を離れる操作で自動歩行を終了する。
避難先側の経路終点から150m以内で、Google撮影・屋外・隣接リンクありのノードを取得する。
そのノードへ接続できない場合、探索済みの接続グラフから道路側の到着点を選ぶ。
候補は元の到着ノードから50m以内・経路終点から150m以内・経路から20m以内・経路残距離150m以内のノードに限り、開始ノードは除外する。
確定したIDを到着地点として体験中のメモリに保持し、地図には「着」で示す。到着判定は確定IDとの一致で行い、歩行中の距離判定には切り替えない。
そのノードへの移動完了で「避難先付近に到着」として停止する。
施設中心から30m以内という判定は行わない。到着ノードを取得できなければ自動歩行を開始しない。
未体験の判断や途中の進捗不足で到着を妨げず、体験した内容だけを振り返る。
これはシミュレーションの終了地点で、実際の施設入口を特定したものではない。
接続がない場合や読み込みに失敗した場合はその場で停止し、API版では想定図で
進行を代替しない。停止中も地図を確認できる。
地図・説明・設定を開いている間は、歩行と判断タイマーを停止する。

## 守っているルール

### 安全表現（仕様 11）
- 実在の建物・塀・道路が壊れると**断定しない**。危険はすべて「〜した想定」と書く。
- 画面上部に「想定シナリオ」の帯を**常時**出す（`/evac/walk`）。
- ストリートビューの上に重ねるのは、半透明の想定範囲と番号だけ。
  実在の建物が損壊して見える加工はしない。
- 「現在のストリートビュー画像だけでは安全性を判定できません」を下部シートに常時出す。
- 経路の説明に「安全です」と書かない。距離・時間・イベント数・曲がる回数など、
  **経路データから言えることだけ**を並べる（`routeNotes()`）。

### データの扱い（仕様 9）
- ストリートビューの画像はアプリ側で保存・キャッシュしない。
- パノラマ ID は体験中のメモリだけに保持する。再読込時は保存した実座標付近から検索する。
- 保存するのは、指定した地点・選んだ避難場所・経路と実際に通った地点の座標・進捗・イベント ID・回答だけ
  （`jishingoto.evac.v2` / `sessionStorage`）。
- 位置情報の使いみちを `/evac` で先に説明する。

### 帰属表示（仕様 7・14）
- Street View の標準コントロールは減らしているが、Google のロゴと帰属表示は消さない。
- 下部シートはパノラマの**外**に置き、パノラマの下端に何も重ねない。

### AI とルールエンジンの分担（仕様 10）
- 判断イベントの中身・選択肢の優先順位は `evac-content.ts` の**ルールデータ**。
  ストリートビューの画像を見て判定してはいない。
- ストリートビュー画像を AI に送る解析は、利用条件と権利処理を確認したあとの将来機能。

### 判断と結果（仕様 6・8）
- 選択は3択（そのまま進む／距離を取る・待つ／迂回する）。正解を当てるクイズにしない。
- 選択直後は短いフィードバックだけ。利点と注意点は結果レポートでまとめて出す。
- 迂回を選ぶと、この先の判断地点が別ルートのものに差し替わる。
- 結果は点数を主役にせず、「避けられた危険」と「次回の判断基準」、
  そして**平常時に確認すること**をひとつ選んでもらう形にしている。
- 制限時間は既定10秒。時間設定から「10秒ふやす」「制限なし」を選べる。
  時間が0秒になっても自動回答せず、本人が行動を選ぶ。

## ハッカソン版の範囲（仕様 13）

- 対象地域：どこでも可（住所・現在地・地図タップで指定）。デモ地点は文京区大塚 付近

## 経路に合わせた地形データ取得

`mayuka/dynamic-route-geodata` では、地理データ＋AIの出題と候補経路の地形比較に、経路周辺の動的取得を追加した。収録済みの文京・横浜に収まる経路は既存データを使い、それ以外は国土地理院の地形分類（自然地形）のズーム14 GeoJSONを取得する。開始地点の例は地域制限ではない。

- 経路を約20m間隔で補間し、各点の周囲80mにかかるタイルを取得する。長い直線区間やタイル境界の隣接地物も対象にする。
- 1経路につき最大64タイル、4並列、取得全体12秒、1タイル8MB。成功したタイルと404はサーバープロセスのメモリに1時間、最大64件保持する。Vercelのファイル書き込みや追加キーは不要。通信失敗はキャッシュしない。
- 404・空データ・未対応分類による欠落と、通信失敗・不正なGeoJSONを区別する。経路上の約20m間隔の点が地形ポリゴンに含まれるか（境界誤差1m）確認し、欠落を「注意候補なし」として扱わない。この確認はデータ被覆のサンプリングであり、実地の安全・通行可能性の保証ではない。
- 分類名・成因・リスク説明は国土地理院の公開style.jsから抽出した `classifications.json` を使用する。外部JavaScriptは実行しない。出題対象カテゴリは既存の分類対応を維持し、地すべり地形に斜面の観点を追加した。未知コードは推測しない。
- 証拠にはタイル・形状に由来する地物ID、データと分類辞書のハッシュ、取得日時を残す。位置を変更しても固定問題へ自動的には切り替えない。提供範囲外では固定の練習問題への切り替えを案内する。
- 地形比較はデータ取得に失敗してもGoogleの距離・時間を表示し、地形の比較点は付けない。出題の通信待ちは最大55秒（地形取得12秒＋既存AI処理35秒を含む）。Street Viewの収録・ノード接続は別途確認する。

出典：[国土地理院ベクトルタイル提供実験（地形分類）](https://github.com/gsi-cyberjapan/experimental_landformclassification)、[分類定義](https://cyberjapandata.gsi.go.jp/xyz/experimental_landformclassification1/style.js)。分類定義の取得日：2026-09-13。国土地理院データを加工して作成。[利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)。

実データの確認：大阪（34.702,135.495）、名古屋（35.1709,136.8815）、札幌（43.0686,141.3508）から北へ約111mの経路で、地形取得・被覆確認に成功。AI出題からStreet View歩行完了までの実サービス通し確認は未実施。


### Street View事前接続確認の実データ対応

開始点・到着候補の検索はOUTDOORとGOOGLEの両条件を使い、独立した投稿パノラマが混入するのを避ける。歩道と撮影位置のずれを考慮して経路沿い40m以内を探索し、経路上への投影が後退した場合は接続を削除せず探索コストを加算する。投影が前へ飛ぶ場合も、間の経路頂点が実リンク区間またはそこまでのノード列の20m以内なら接続を認める。大きな角の省略は引き続き拒否する。取得失敗・探索上限・本当に接続候補がない場合の案内を分ける。


## 場所選び・災害ケース

入口では出題方法を選ばせず、住所・現在地・地図で場所を選ぶ。現在地取得は「現在地から始める」の文字付きボタンから行い、拒否・タイムアウト時も住所検索へ進める。「どの道で行こう？」画面に地震／洪水のケース選択を設けた。場所選びでは両ケースの指定場所を候補にする。ケース変更時は同じ画面で、選択中の避難先が対応しているかを確認して経路を再計算する。非対応ならその画面で対応する避難先を選び直す。歩行記録・回答は初期化し、古い非同期検索の結果を適用しない。

通常のAPI体験は地理データ＋AIで出題する。固定問題の選択は解析失敗画面にだけ表示し、代替問題であることを歩行画面にも明示する。新しい場所・ケース・体験では再び通常の解析を試す。地図自体が使えない場合のサンプル版は引き続き利用できる。

洪水ケースでは洪水に対応する指定緊急避難場所へのGoogle徒歩経路を用意し、地形分類のうち氾濫平野・後背低地・旧河道・落堀・河川敷・凹地の一般的な傾向を比較と出題に使用する。ケースは候補比較・AI入力・迂回検索・迂回後の出題まで引き継ぐ。洪水の固定問題も洪水用とし、地震の問題には切り替えない。

これは浸水が始まる前の避難を考える練習。洪水の経路生成・比較には下記の浸水想定タイルを使用する。現在の水位や通行止めは未取得。指定緊急避難場所（災害から緊急に逃れる場所）と指定避難所（滞在施設）の区分も詳細で説明する。

判断のふりかえりは利点を暖色（amber）、気をつけたい点を寒色（blue）で表示する。

出典：[国土地理院：指定緊急避難場所・指定避難所データ](https://www.gsi.go.jp/bousaichiri/hinanbasho)、[内閣府：風水害から身を守る](https://www.bousai.go.jp/kohou/kouhoubousai/h24/67/special_01.html)。


### 洪水ハザードに基づく候補生成・比較

- 出典：重ねるハザードマップ「洪水浸水想定区域（想定最大規模）」の国・都道府県管理河川統合タイル。URL・凡例は https://disaportaldata.gsi.go.jp/hazardmap/copyright/opendata.html 。凡例は `shinsui_legend3.png` に合わせる。
- サーバーでズーム16のPNGを取得し、経路上を5m間隔で照合。最も深い着色区分、着色・無着色・判定不能の区間長を別々に保存する。距離は標本点の代表区間長を合計し、Googleの経路全長に合わせて補正した概算。無着色は未指定・未収録を含み、404・通信失敗・未知の色は判定不能として扱う。
- 着色区間から100/250/500/1000mの両側を調べ、取得できたより浅い区分または無着色の地点を経由点候補にする。最大4地点でGoogle徒歩経路を再取得し、引き返しと頂点の分割・丸めだけが違う同じ道を除外して経路全体を再評価する。経由点だけの評価では採用しない。最短経路との距離比による足切りはしない。
- 取得できた候補を優先し、深さ区分の重み（浅い順1〜8）×着色区間長、着色区間長、距離の順で最大3本を提示する。比較専用の順序であり、物理的な被害予測ではない。地形比較の順位を洪水の推薦順位として使わない。
- データ取得は1評価12秒・80タイルまで。成功タイルのみプロセス内で最大128枚・1時間キャッシュする。地形データ取得と独立して動き、未取得時は既存経路を残して取得状況を表示する。
- 準備・歩行中の地図・ふりかえりに同じ配信タイルを重ね、凡例と出典を表示する。地震の経路生成と、AIの地形に基づく出題は従来どおり。

### 歩行中の想定問題

通常の API 体験は `/api/evac/scenarios` で周辺条件に合う問題候補を準備する。候補取得の3問制限と、迂回時の残り3問という制限は撤廃した。洪水は8–10、地震の住宅周辺は11–20を候補にし、工場・中高層建物・商業施設周辺の問題も災害条件に応じて追加する。条件に合う問題が足りない場合は21–30の共通問題からランダムに補充する。ルート復帰の23は出題しない。階段、同行者、到着時の受付などの未確認の条件は明示的な仮定として提示する。洪水1–7のルート比較問題は歩行中に出さない。

出題位置と必要数は接続確認済みのStreet Viewノードから決め、8・16・24…ノード目に1問ずつ配置する。問題数に上限は設けない。8ノード未満の経路や端数区間に追加出題はせず、到着が8ノード目なら回答後に完了する。APIの候補数にかかわらず不足分は共通問題で補う。迂回は回答したノードを起点に再配置し、過去の回答履歴を保持する。共通問題は未出題を優先し、全種類を使い切った場合のみ新しい一巡を開始する。通常の歩行問題30種類は、明示した条件で行動の優先順位を比較する3択とし、選択肢の順序を出題時にシャッフルする。選択ごとの利点と不足点を振り返りに表示する。固定のモック・サンプル体験は従来の練習用配置を維持する。回答待ち・経路再計算中は自動歩行を止め、設定自体は維持する。迂回の選択は実際に滞在している座標から災害別の経路検索を再実行し、同じ道しか得られない場合は回答を確定せず再試行を案内する。現地の規制・冠水をRoutes APIが検知した意味ではない。

周辺分類には国土数値情報「都市地域土地利用細分メッシュ」の100mセルと周囲8セルを使う。0703/0704が3セル以上なら低層住宅周辺、0702が2セル以上または当該セルなら工場周辺、0701が2セル以上または当該セルなら中高層建物周辺とする。建物の用途や高さ、設備、現在の被害を個別に確定するものではない。公開地域の2021年を優先し、未更新地域は2016年を使用する。対象外・取得失敗は共通問題で補う。

東京(5339)・大阪(5235)は公式ZIPから作った圧縮グリッドを同梱。全122メッシュの公開カタログのうち他の地域は必要時に公式ZIPを取得し、メモリーに最大12枚キャッシュする（取得上限12秒、ZIP25MB、DBF32MB、1経路最大4枚）。再生成: `python3 scripts/prepare-urban-landuse.py catalog.html primary.zip ...`。同梱ファイルの0は未収録、1=0701、2=0702、3=0703、4=0704、5=その他の収録分類。元データ: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-L03-b-u-v3_1.html （2026-09-14取得）。

メッシュには商業地の区分がないため、商業施設周辺だけは任意のGoogle Places API (New)で補完する。ブラウザのMapsキーでPlaces API (New)が利用できる場合、経路上の3地点・半径150mでshopping_mall/department_store/supermarketを最大4件ずつ検索し、施設から120m以内の地点に出題する。検索結果なし・権限不足・4秒超過では商業施設周辺とみなさず、他の分類または共通問題を使う。用途地域としての「商業地」や実際の渋滞を断定しない。Places検索にはGoogle側の課金・キー設定が適用される。画像やStreet View写真のAI解析は行わず、この出題経路にOpenAIキーは不要。旧 `/api/evac/analyze` は既存の地形解析用として残す。

歩行中の通常状態テキストは下部に置かず、Street View上の左上に自動走行モードのバッジを表示する。回答通知・自動走行開始でStreet Viewの高さを変えない。出題の到達判定は現在のパノラマIDを接続確認済み計画のノードへ照合し、そのノードに配置した問題IDを使う。SDKが返す現在座標と事前取得座標が数m異なる場合も出題できる。回答によって出題スケジュールをリセットしない。

### 到着後の振り返り

到着のチェックマーク下の「ふりかえる」から `/evac/report` で地図と判断記録を確認し、「判断のスコアを見る」で `/evac/summary` へ進む。後半には判断スコア、良かったところ、改善できるところ、選択して保存する「次に確かめること」を配置する。

スコアは設問ごとに選択肢の優先度を正規化した平均（優先度1=0点、最高優先度=100点、優先度2/最高3=50点）。時間・距離・実際のハザード量は採点しない。評価可能な回答数を表示し、0件なら点数なし。これは今回の想定問題の評価であり、実際の避難の安全性や災害時の対応力の保証ではない。良かったところは最優先の行動を選んだ回答、改善点はそれ以外の回答に対して最優先の行動と設問のヒントを示す。


### イラストと読む時間

通常の歩行問題30種類に、状況図と各選択肢の行動図を用意した（30場面・90行動）。人物・移動方向・確認する道具で行動を描き分け、正解を示す色や記号は使わない。テキストは条件の補足として残し、絵には代替説明を付ける。地図画像やStreet Viewから作る図ではなく、外部画像APIを使わない想定図である。モック・旧問題にも種類別の状況図と行動図を表示する。

出題時の時計は確認中として停止し、時間制限ありでは「判断を始める」で計測を始める。「時計を止めて、もう一度確認する」は残り時間を保持して停止し、「時間制限なしで選ぶ」で計測を解除する。時間切れで自動回答しない。イラスト付きカードの本文と選択肢はスクロール可能、時計と開始操作は固定表示にする。

通常の歩行問題30問は、内蔵画像生成で事前作成したV2のWebP120枚（各問の状況＋3選択肢）を使用する。保存先は `public/illustrations/evac/walk-case-番号/*-v2.webp`。問題IDと選択肢IDを使って対応させ、選択肢の表示順には依存しない。固定練習用の4問・対象外の問題はSVGを使用する。実行時の画像生成は行わない。SVG一覧のモックページは削除済み。

全30問の構図と選択肢ID対応、スマホ相当の縮小比較、生成指示は `docs/illustrations/` に保存している。[残り20問の制作結果](illustrations/remaining-review-v2.md)に制作時の確認結果と制約を記録した。
