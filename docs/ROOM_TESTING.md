# APIを繰り返し呼ばない部屋テスト

カメラ画面の「APIを使わずテストする」、または `/test-room` から開始します。

## APIなし

- リポジトリの `public/figma/img/room-risk.jpg` と固定解析結果を利用。
- 予想図の代わりにも同じ元写真を表示（生成された地震後の図ではない旨を表示）。
- 解析・生成の模擬待ち時間を各0〜180秒で指定。例：解析2秒／生成20秒、生成120秒で待機画面を検証。
- このモードでは `/api/room/analyze` と `/api/room/aftermath` を呼ばない。
- 写真・実際のAPIレスポンスを新たに保存する機能はない。モードと計測はメモリ内のみ。

## 実測（API課金あり）

「実測するため写真を撮る」で撮影し、ぼかし確認のOK後に各APIを1回並行実行。
解析中・認識確認・結果画面の「処理時間・テスト情報」に通信込みの所要時間と成功／代替表示を表示。
模擬時間では実際のAPI速度は判定できないため、必要な時だけ実測する。
同じ写真の結果表示では再生成しない。別写真・マスク変更・セッションリセット後は再実行。
計測はリクエスト開始から完了まで。解析画面の約4.2秒の演出や撮影・マスク時間は含まない。
テストモードから通常のぼかし確認に進む場合は通常モードへ戻る。

## 自動検証

`node --test tests/room-flow.test.cjs`

APIなし・模擬時間・解析前の画像生成開始・重複防止・古い結果との競合・番号フォーカス・家具分類と対策を検証。実際のOpenAI APIは呼ばない。

- [東京消防庁：自宅の家具転対策](https://www.tfd.metro.tokyo.lg.jp/lfe/bou_topic/kaguten/measures_house.html) — 家具別の固定、食器棚の扉開放防止、テレビ本体と台の対策。
- [東京消防庁：地震に対する10の備え](https://www.tfd.metro.tokyo.lg.jp/lfe/bou_topic/jisin/sonae10.html) — 家具・収容物の備え、靴と明かり。
- [東京都：地震発生時の行動](https://www.bousai.metro.tokyo.lg.jp/bousai/1000026/1005642.html) — 揺れが収まってから出口を確保。

写真だけで固定状態や実際の被害を断定しない。棚上の物と床置きの物を別分類とし、子どもだけで家具を動かす／破片を片付けるように案内しない。
